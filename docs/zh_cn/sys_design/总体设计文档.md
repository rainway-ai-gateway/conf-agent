# conf-agent 总体设计文档

## 1. 概述

### 1.1 定位

`conf-agent` 是 AI 网关的**配置代理组件**，负责从 `ai-gateway-api` 控制面拉取最新的 BFE 数据面配置，并触发 BFE 热加载。它向下屏蔽了配置获取、版本比对、本地落盘、目录切换等细节，使 BFE 能够无中断地感知控制面下发的策略变更。

本文档用于帮助读者和大模型快速建立对 `conf-agent` 系统设计的整体认知。关于配置加载与热加载的详细流程，请阅读同目录下的《details/配置加载与热加载流程.md》。

### 1.2 项目上下文

AI 网关整体由以下核心组件构成：

| 组件 | 角色 | 说明 |
|------|------|------|
| **AI Gateway API** | 控制面 | 负责配置管理、版本控制和配置导出 |
| **BFE** | 数据面 | 流量转发与访问控制，通过热加载读取最新配置 |
| **Conf Agent** | 配置代理 | 即本项目，负责从 InnerAPI 拉取配置并触发 BFE 热加载 |
| **Dashboard** | 管理控制台 | Web UI，调用 OpenAPI 完成可视化操作 |

### 1.3 功能范围

`conf-agent` 当前代码实现的功能范围如下：

- **多模块配置拉取**：每个 `Reloader` 独立负责一类 BFE 模块配置（如 `mod_ai_token_auth`、`tls_conf` 等），可并行运行。
- **增量版本探测**：通过比对本地配置文件中的 `Version` 字段与远程 `ai-gateway-api` 返回的数据，决定是否拉取新配置。
- **三类文件任务**：
  - `NormalFileTask`：一个 InnerAPI 对应一个本地配置文件。
  - `MultiKeyFileTask`：一个 InnerAPI 返回多个配置文件内容，按 key 映射为多个本地文件。
  - `ExtraFileTask`：在 `NormalFileTask` 基础上，解析配置文件中的附加文件路径并额外下载。
- **本地目录版本管理**：每次拉取到新配置后，创建带版本号后缀的临时目录（如 `mod_ai_token_auth_20260730144012`），并通过符号链接指向最新目录。
- **BFE 热加载触发**：通过调用 BFE Monitor 端口的 `/reload/{module}` 接口通知 BFE 读取新目录中的配置。
- **配置继承**：通过 `CopyFiles` 机制将 BFE 冷启动必需的静态文件从当前配置目录复制到新版临时目录。

## 2. 架构总览

### 2.1 组件交互关系

```
┌─────────────────┐      InnerAPI (HTTP GET)       ┌─────────────────┐
│  ai-gateway-api │  ◄────────────────────────────  │   conf-agent    │
│  (控制面)        │                                 │  (配置代理)      │
└─────────────────┘                                 └────────┬────────┘
                                                             │
                              HTTP GET /reload/{module}      ▼
                                                    ┌─────────────────┐
                                                    │       BFE       │
                                                    │    (数据面)      │
                                                    └─────────────────┘
```

- `conf-agent` 不会被动接收通知，而是**周期性轮询** `ai-gateway-api` 的 InnerAPI 导出接口。
- 每次拉取时携带本地版本号，服务端仅在配置有更新时返回非空数据；无更新时返回 `null`。
- 新配置落盘并通过 BFE 热加载接口通知 BFE 后，`conf-agent` 切换本地符号链接，使后续 BFE 重启或新进程读取最新目录。

### 2.2 内部分层架构

```
┌─────────────────────────────────────────────────────────────┐
│  main.go                                                     │
│  解析命令行参数 → 加载配置 → 初始化日志 → 启动 Agent           │
├─────────────────────────────────────────────────────────────┤
│  agent/agent.go                                              │
│  管理多个 Reloader，每个 Reloader 独立运行在一个 goroutine    │
├─────────────────────────────────────────────────────────────┤
│  conf_reload/reloader.go                                     │
│  编排单次 reload 流程：probe → store → trigger → update link  │
├─────────────────────────────────────────────────────────────┤
│  conf_reload/prober/        conf_reload/file_store/          │
│  conf_reload/trigger/                                        │
│  配置探测与拉取              配置落盘与符号链接切换            │
│  BFE 热加载触发                                              │
├─────────────────────────────────────────────────────────────┤
│  config/         xhttp/         xfile/         xlog/         │
│  配置解析         HTTP 请求封装    文件操作封装     日志上下文  │
└─────────────────────────────────────────────────────────────┘
```

| 层次 | 主要职责 | 关键包 |
|------|----------|--------|
| **入口与初始化** | 解析参数、加载 TOML 配置、初始化日志、创建 Agent | `main.go`、`config` |
| **Agent 层** | 持有并启动所有 Reloader，提供停止通道 | `agent` |
| **Reload 编排层** | 按固定周期触发 reload，协调 probe、store、trigger、update 四个阶段 | `conf_reload` |
| **能力子模块** | 分别实现配置探测、文件落盘、BFE 热加载触发 | `conf_reload/prober`、`conf_reload/file_store`、`conf_reload/trigger` |
| **工具库** | HTTP 请求、文件操作、日志格式化与上下文传递 | `xhttp`、`xfile`、`xlog` |

### 2.3 数据流

```
main.go
  │
  ├─ config.Init() ──► 解析 conf-agent.toml
  │
  ├─ xlog.Init() ──► 初始化日志 writer
  │
  └─ agent.New() ──► 为每个 ReloaderConfig 创建 Reloader
       │
       └─ agent.Start() ──► 为每个 Reloader 启动 goroutine
            │
            ▼
       Reloader.Start()
            │
            ├─ Probe() ──► 从 ai-gateway-api 拉取配置
            │
            ├─ StoreFile2TmpDir() ──► 写入 ConfDir_<version>
            │
            ├─ TriggerBFEReload() ──► 通知 BFE 热加载
            │
            └─ UpdateDefaultConfDir() ──► 切换 ConfDir 符号链接
```

### 3.1 顶层目录结构

```
conf-agent/
├── main.go                          # 服务入口

├── docs/zh_cn/                      # 中文文档
│   ├── README.md
│   ├── config/
│   │   └── config.md                # 配置项说明

│       ├── summary.md
│       ├── 总体设计文档.md
│       └── details/
│           └── 配置加载与热加载流程.md
├── agent/                           # Agent：Reloader 生命周期管理
├── config/                          # TOML 配置解析与配置模型
├── conf_reload/                     # 配置 reload 核心逻辑
│   ├── reloader.go                  # reload 流程编排
│   ├── file_store/                  # 文件落盘与符号链接切换
│   ├── prober/                      # 配置探测与拉取
│   │   ├── task_normal.go
│   │   ├── task_multip_key.go
│   │   └── task_extra.go
│   └── trigger/                     # BFE 热加载触发
├── xfile/                           # 文件操作工具
├── xhttp/                           # HTTP 请求封装
├── xlog/                            # 日志封装
└── version/                         # 版本常量
```

### 3.2 关键包职责

| 包 | 职责 |
|----|------|
| `agent` | 持有所有 `Reloader` 实例，启动和停止轮询 goroutine。 |
| `config` | 定义 `Basic`、`Logger`、`Reloader`、`Task` 等配置结构，使用 TOML 反序列化并填充默认值。 |
| `conf_reload` | `Reloader` 的实现，按 `ReloadInterval` 周期执行 `probe → store → trigger → update`。 |
| `conf_reload/prober` | 根据任务类型从 `ai-gateway-api` 拉取配置，返回 `FetchFileResult` 列表。 |
| `conf_reload/file_store` | 将配置写入临时目录、复制 `CopyFiles`、切换符号链接。 |
| `conf_reload/trigger` | 调用 BFE `/reload/{module}` 接口，传入新版本目录路径。 |
| `xhttp` | 基于 `net/http` 的链式请求封装，支持超时、Header、状态码校验、JSON 反序列化。 |
| `xfile` | 文件拷贝、递归拷贝、符号链接/目录连接创建、非链接文件重命名等工具函数。 |
| `xlog` | 基于 `go-lib/log/log4go` 的日志封装，提供 `LogID` + `ReloaderName` 的上下文日志格式。 |

## 4. 启动流程

```
main.go
  │
  ├─ flag.Parse()                       # 解析 -c / -cf / -h / -v
  │
  ├─ config.Init(filepath.Join(*confDir, *confFile))
  │     ├─ LoadConf()                   # TOML 反序列化
  │     ├─ merge()                      # Basic 默认值填充到 Reloader
  │     └─ validator.New().Struct()     # 配置校验
  │
  ├─ xlog.Init(conf.Logger)             # 初始化文件日志
  │
  ├─ agent.New(conf.Reloaders)
  │     └─ 为每个 ReloaderConfig 创建 conf_reload.Reloader
  │
  └─ agent.Start()
        └─ 为每个 Reloader 启动 goroutine，执行 Reloader.Start()
```

`Reloader.Start()` 启动后会先随机睡眠一段不超过 `ReloadInterval` 的时间，避免多个 Reloader 同时请求 `ai-gateway-api`。

## 5. 配置模型

`conf-agent` 的配置文件采用 TOML 格式，分为三大部分：`Logger`、`Basic`、`Reloaders`。

### 5.1 Logger

| 字段 | 说明 |
|------|------|
| `LogDir` | 日志文件目录 |
| `LogName` | 日志文件名 |
| `LogLevel` | 日志级别：DEBUG / TRACE / INFO / WARNING / ERROR / CRITICAL |
| `RotateWhen` | 日志切割策略：M / H / D / MIDNIGHT |
| `BackupCount` | 保留日志文件数量 |
| `Format` | 日志格式 |
| `StdOut` | 是否同时输出到控制台 |

### 5.2 Basic

| 字段 | 说明 |
|------|------|
| `BFECluster` | 当前 BFE 集群名，用于 InnerAPI 的 `bfe_cluster` 参数 |
| `BFEConfDir` | BFE 配置根目录，默认 `/home/work/bfe/conf` |
| `BFEMonitorPort` | BFE Monitor 端口，默认 `8421` |
| `BFEReloadTimeoutMs` | BFE reload 请求超时，默认 `1500` ms |
| `ReloadIntervalMs` | 拉取配置周期，默认 `10000` ms |
| `ConfServer` | `ai-gateway-api` 地址 |
| `ConfTaskHeaders` | 拉取配置时携带的 HTTP Header，通常包含 Authorization |
| `ConfTaskTimeoutMs` | 拉取配置超时，默认 `2500` ms |
| `ExtraFileServer` | 附加文件服务器地址 |
| `ExtraFileTaskHeaders` | 附加文件请求 Header |
| `ExtraFileTaskTimeoutMs` | 附加文件下载超时，默认 `2500` ms |

### 5.3 Reloader

`Reloaders` 是一个 map，key 为模块名（如 `mod_ai_token_auth`），value 为 `Reloader` 配置。未设置的字段自动继承 `Basic`。

| 字段 | 说明 |
|------|------|
| `ConfDir` | 模块配置本地目录，默认 `{BFEConfDir}/{reloaderName}` |
| `BFEReloadAPI` | BFE reload 接口路径，默认 `/reload/{reloaderName}` |
| `ReloadIntervalMs` | 该模块的拉取周期 |
| `CopyFiles` | 需要从当前配置目录复制到新版临时目录的文件/目录列表 |
| `NormalFileTasks` | 普通文件任务列表 |
| `MultiKeyFileTasks` | 多 key 文件任务列表 |
| `ExtraFileTasks` | 带附加文件的任务列表 |

## 6. 设计原则与约定

1. **模块隔离**：每个 `Reloader` 独立运行，互不影响；一个模块的 reload 失败不会阻塞其他模块。
2. **无状态**：`conf-agent` 不维护持久化状态，所有版本信息来自本地配置文件中的 `Version` 字段。
3. **幂等拉取**：通过本地版本号实现增量拉取，服务端返回 `null` 时跳过本次 reload。
4. **先写临时目录、再切换符号链接**：确保 BFE 热加载读取到的配置始终完整。
5. **失败不中断主流程**：`TriggerBFEReload` 失败后不会执行符号链接切换；`UpdateDefaultConfDir` 失败只记录日志，不影响下一次 reload。
6. **跨平台兼容**：`xfile.FileLink` 在 Windows 使用目录连接（junction），在 Unix 使用符号链接。
7. **日志可追踪**：每个 `Reloader` 的日志包含独立的 `LogID` 和模块名，便于定位问题。
