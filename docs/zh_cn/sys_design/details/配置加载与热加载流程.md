# conf-agent 配置加载与热加载流程

## 1. 流程概览

`conf-agent` 的核心职责是：周期性地从 `ai-gateway-api` 拉取最新配置，安全地落盘到本地，并触发 BFE 热加载，使 BFE 在不重启的情况下使用新配置。

单次 reload 的完整流程由 `conf_reload/reloader.go` 编排：

```
┌─────────┐   ┌─────────────────┐   ┌─────────────────┐   ┌─────────────────┐
│  Probe  │ → │ StoreFile2TmpDir │ → │ TriggerBFEReload │ → │ UpdateDefaultConfDir │
└─────────┘   └─────────────────┘   └─────────────────┘   └─────────────────┘
 拉取配置         写入临时目录            触发 BFE 热加载          切换符号链接
```

- 如果 `Probe` 返回空（无新配置），流程直接结束。
- 任何阶段失败都会中断后续阶段，但 `UpdateDefaultConfDir` 的失败只记日志，不影响下一次 reload。

## 2. Probe：配置探测与拉取

### 2.1 入口

`Reloader.reload()` 调用 `prober.Probe(ctx)`，由 `Prober` 遍历其持有的所有 `Task`，聚合返回 `[]*FetchFileResult`。

### 2.2 任务类型

| 任务类型 | 说明 | 典型使用场景 |
|----------|------|--------------|
| `NormalFileTask` | 一个 InnerAPI 对应一个本地配置文件 | `mod_ai_token_auth`、`tls_conf` 等 |
| `MultiKeyFileTask` | 一个 InnerAPI 返回多个配置文件内容，按 key 映射为多个本地文件 | 一个接口返回多份子配置 |
| `ExtraFileTask` | 在 `NormalFileTask` 基础上，解析主配置中的附加文件路径并额外下载 | 证书、密钥等附加文件 |

### 2.3 本地版本读取

对于 `NormalFileTask` 和 `MultiKeyFileTask`，任务会先读取本地配置文件中的 `Version` 字段：

```go
version := justKeepNumber(tmp.Version)
if version == "" {
    version = "00000000000000"
}
```

- 将 `Version` 中的非数字字符去除，得到纯数字版本号。
- 如果本地文件不存在或 `Version` 为空，则使用默认版本号 `00000000000000`。

### 2.4 远程拉取

任务向 `ai-gateway-api` 发送 HTTP GET 请求，携带两个参数：

- `version`：本地版本号
- `bfe_cluster`：当前 BFE 集群名

请求示例：

```http
GET /inner-api/v1/configs/mod-ai-key?version=20260730133856&bfe_cluster=default HTTP/1.1
Host: ai-gateway-api
Authorization: Bearer <token>
```

服务端行为：

- 如果远程版本号与本地一致，返回 `{"ErrNum": 200, "Data": null}`。
- 如果有更新，返回 `{"ErrNum": 200, "Data": <config>}`。

### 2.5 版本计算

拿到远程配置内容后，再次解析其 `Version` 字段并去除非数字字符，作为本次写入的 `version`。

## 3. StoreFile2TmpDir：配置落盘

### 3.1 临时目录命名

临时目录命名为 `ConfDir + "_" + version`，例如：

```text
/home/work/bfe/conf/mod_ai_token_auth_20260730144012
```

### 3.2 写入步骤

1. **删除已存在的同名临时目录**：避免历史残留。
2. **创建临时目录**：使用 `os.MkdirAll` 创建。
3. **复制 `CopyFiles`**：将 `CopyFiles` 中指定的文件/目录从当前 `ConfDir` 复制到临时目录。这些文件通常是 BFE 冷启动必需、但不会被 InnerAPI 更新的静态配置。
4. **写入新配置内容**：将 `FetchFileResult` 中的内容以格式化后的 JSON 写入临时目录。

### 3.3 目录结构示例

```text
/home/work/bfe/conf/mod_ai_token_auth_20260730144012/
├── mod_ai_token_auth.json      # NormalFileTask 写入
├── mod_ai_token_auth_rule.json # MultiKeyFileTask 写入
├── server.crt                  # ExtraFileTask 下载的附加文件
└── .conf-agent-version         # （优化后）版本标识文件
```

## 4. TriggerBFEReload：触发 BFE 热加载

### 4.1 调用方式

`Trigger` 构造 BFE Monitor 的 reload URL：

```text
http://127.0.0.1:{BFEMonitorPort}/reload/{module}?path={ConfDir}_{version}[/{ReloadFile}]
```

示例：

```text
http://127.0.0.1:8421/reload/mod_ai_token_auth?path=/home/work/bfe/conf/mod_ai_token_auth_20260730144012
```

### 4.2 BFE 行为

BFE 收到 reload 请求后：

1. 读取指定目录下的配置文件；
2. 在内存中重新构建对应模块的配置；
3. 对新请求使用新配置，旧请求继续沿用旧配置（请求级别无中断）。

### 4.3 失败处理

如果 `TriggerBFEReload` 失败，`Reloader.reload()` 会直接返回，不会执行 `UpdateDefaultConfDir`。此时：

- 临时目录仍然保留；
- 符号链接仍指向旧目录；
- 下一次 reload 会重新创建临时目录并再次尝试。

## 5. UpdateDefaultConfDir：切换符号链接

### 5.1 当前实现

`file_store.UpdateDefaultConfDir` 负责将正式配置路径 `ConfDir` 的符号链接指向最新临时目录：

```go
dest, err := filepath.EvalSymlinks(fileStore.ConfDir)
if err != nil {
    return err
}

// 删除符号链接本身
os.RemoveAll(fileStore.ConfDir)

// 如果原目标是链接，再删除链接指向的真实目录
if dest != fileStore.ConfDir {
    os.RemoveAll(dest)
}

// 建立新符号链接
xfile.FileLink(fileStore.tmpDir(version), fileStore.ConfDir)
```

### 5.2 正常切换示例

切换前：

```text
/home/work/bfe/conf/
├── mod_ai_token_auth -> /home/work/bfe/conf/mod_ai_token_auth_20260730133856
└── mod_ai_token_auth_20260730133856/
```

切换后：

```text
/home/work/bfe/conf/
├── mod_ai_token_auth -> /home/work/bfe/conf/mod_ai_token_auth_20260730144012
└── mod_ai_token_auth_20260730144012/
```

### 5.3 存在问题

当前实现只删除“上一个”符号链接目标目录，存在以下隐患：

- 历史上因进程异常、切换失败等原因遗留的目录不会被清理；
- 对符号链接损坏、缺失、被替换为普通目录等异常场景缺乏容错；
- 没有显式标识哪些目录是 `conf-agent` 生成的，存在误删风险。

针对该问题的优化方案详见 `conf-agent/docs/zh_cn/modifications/2026-08-28-conf-dir-cleanup/design-changes.md`。

## 6. 异常处理与边界情况

| 场景 | 当前行为 | 说明 |
|------|----------|------|
| 无新配置 | `Probe` 返回空，`reload` 直接结束 | 避免不必要的文件操作和 BFE 热加载 |
| 拉取配置超时 | 记录错误，本次 reload 失败 | 下次周期重试 |
| BFE reload 失败 | 不切换符号链接 | 保证 BFE 仍读取旧目录中的稳定配置 |
| `UpdateDefaultConfDir` 失败 | 记录错误，不影响下一次 reload | 但当前代码会在错误时仍打印 `succ` 日志，需修复 |
| `ConfDir` 为普通目录 | 当前实现会删除该目录并建立符号链接 | 存在误删风险，优化方案中改为重命名备份 |
| `ConfDir` 不存在 | `EvalSymlinks` 失败，`UpdateDefaultConfDir` 返回错误 | 优化方案中改为直接建立新符号链接 |

## 7. 时序图

```
ai-gateway-api              conf-agent                 BFE          本地文件系统
     │                         │                       │                │
     │◄────────────────────────┤                       │                │
     │   GET /configs/xxx?version=xxx                  │                │
     │                         │                       │                │
     ├────────────────────────►│                       │                │
     │   { "Data": <config> }  │                       │                │
     │                         │                       │                │
     │                         ├── StoreFile2TmpDir() ─┤                │
     │                         │                       │                ├──► 创建 ConfDir_<version>
     │                         │                       │                │
     │                         ├── TriggerBFEReload() ─►                │
     │                         │                       ├── 读取新配置    │
     │                         │                       ├── 热加载完成    │
     │                         │◄──────────────────────┤                │
     │                         │                       │                │
     │                         ├── UpdateDefaultConfDir()               │
     │                         │                       │                ├──► 删除旧链接，指向新目录
     │                         │                       │                │
```
